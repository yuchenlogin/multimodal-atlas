# 公式渲染修复记录

日期：2026-10-13。

## 原因

1. `build.py` 原来的 Markdown 扩展列表没有数学扩展。TeX 下标中的 `_` 被强调语法消费；`attr_list` 又解析 `{...}` 并把内容写入 `<em>` 的属性。HTML 中不仅出现标签，字符次序和大括号也已被修改。
2. MathJax 在浏览器中运行，接收到的是损坏后的 HTML，不能恢复原稿。SigLIP、DPO 只是同一构建错误的两个例子。
3. PDF 转换器 `try_display_math()` 原来只接受内容恰好等于 `$$` 的一行。同一行的 `$$公式$$` 走普通文本路径，首尾美元符号被分别转义为可见文字。
4. 发布仓库只有生成的 HTML，构建脚本却读取仓库外的 `../reports/`。单独克隆 GitHub 仓库不能复现页面。
5. PDF 日志还显示 Latin Modern 正文字体缺少 `π`、`≈`、`≠`、`↔`；URL 提取器把紧随链接的中文括号说明也吞进 `\url{}`，导致说明缺字。多模态生成报告中的长 ELBO 公式也超出了 PDF 正文宽度。

## 修复

- 网页通过 `pymdownx.arithmatex` 的 generic 模式输出不可被普通 Markdown 继续拆分的公式元素；MathJax 仅处理 `.arithmatex` 中的 `\(...\)` / `\[...\]`。
- 同时保留单行和多行的源稿写法，无需逐个改写研究公式。
- PDF 两种行间公式写法统一输出 LaTeX display math；代码先于数学保护，正文缺字符号用 `\ensuremath`，URL 在中文括号前结束。
- 长 ELBO 公式使用 `aligned` 分行，保持公式含义，修复 PDF 中的行间公式溢出。
- 所有报告源稿、PDF 转换器、模板和依赖均纳入仓库；中间文件和检查截图不提交。
- 手机上的长行间公式在公式区域滚动，避免撑开整个页面。

## 验证

- Python 回归检查：全部生成 HTML 的公式内容与源稿逐项相同；公式内无 Markdown 标签；检查单行、多行、行内、表格、代码和价格。
- LaTeX 检查：每份报告行间公式数量与源稿一致，输出中没有旧式的 `\$$` 错误。
- Playwright：13 篇报告、589 个公式全部生成 MathJax SVG，未发现 TeX 错误；1440px 和 390px 视口均无页面横向溢出。
- Tectonic：重新编译全部 13 份报告 PDF，日志保存在本地 `tex/`。
- 最终 PDF 日志没有缺字，也没有行间公式超出正文宽度的警告。少量原有表格和参考文献的长文本行警告仍在，未涉及本次公式修复。
